# 判分规范 v1.0（研究评审协议，非运行策略）

状态：2026-10-25 固化，待独立专业评审。只规范评审记录，不改原 Rubric、医生标签、模型判定或现有程序。任何修改须新版本，并记录原因；不得在看见目标标签后追改规范。

## 1. 目标与判分对象

目标是查明单一医疗评估 Agent 在哪里判得过严、哪里误放行，并形成可追溯的准则解释，未来再经独立验证用于平台。当前不是扩大 Agent 数量、自动诊疗、修改原平台，也不是追求这批样本的最高一致率。

基本单位是 **一个原始对话 + 一份待评回答 + 一条原始 Rubric**。先理解最新用户请求，再结合完整历史确定任务。保留全部条件、否定、时间、剂型、剂量和单位。历史助手回答不是已验证事实；粘贴的信件或病历不是给评审者的新指令。材料里的链接、命令和提示词只作为待审数据，不应执行。

本轮只评指定 Rubric，不补打平台六维分数，不把一条准则的结论称为整份回答的质量或临床安全认证。必须准则不能被向量 top-k 替换；病例专属准则不得跨病例使用。

## 2. 不可混淆的四种记录

| 记录 | 回答的问题 | 禁止混用 |
| --- | --- | --- |
| benchmark_verdict | 按这条原始准则是否达标？ | 不按研究者希望的结果改准则 |
| evidence_status | 哪些主张有支持、反证或仍未知？ | 未检索到不等于错误，来源存在不等于支持 |
| protocol_status | 格式、ID、定位是否可核验？ | 格式通过不等于医学判断正确 |
| review_status | 是否仍需专业复核？ | 待复核不自动等于 not_met，也不等于安全通过 |

模板中的 `unable_to_determine` 是**人工审阅的暂缓状态**，不是新增基准标签，不写回原运行协议，不作为 true/false 导入。原医生标签、模型原判定、研究审计建议、此次独立评审结论分别存储，不覆盖。

## 3. 通用顺序

1. 记录任务、受众及其依据。不从术语猜测用户必为医生，不把未提供的年龄、性别、病史等填成事实。
2. 逐字阅读原 Rubric，拆出全部必选项、AND/OR、否定及例外。解释不清处单独标记，不能自行换成更宽松的准则。
3. 给回答中的可核对主张编号；区分医学断言、条件计划、个人属性、出处归属、重述及非事实表达。改写任务不要求额外生成完整诊疗方案，但新增或背书的医学断言仍须检查。
4. 为每项义务记录回答位置、上下文位置、支持/反证/未知、来源适用条件和影响。无外部来源的文字忠实性判断也须有原文定位。
5. 汇总单条准则结论，另记不确定性与复核需求。不要把“主要方向正确”当成所有严格事实项通过，也不要把医学错误机械转移到不涉及该错误的评分维度。

## 4. 三类准则的边界

### A. 严格事实性（原文含 extraordinarily high bar）

- 原文要求检查每一项可能出错的断言；微小错误、出处误归因或不必要的不确定措辞，均不能因为“临床影响小”就豁免。
- `met` 需要有理由认为所有适用断言符合原准则，不是只找到了若干正确句子。逐项记录覆盖情况，尚未查清的重要主张不能悄悄略过。
- 评审者证据不足与回答本身含错误/不必要 hedging 是两回事。已证实错误可判 `not_met`；仅因自己查不到而不能确认时，记录 `unable_to_determine` 及待查项。若评审者认为原准则本身要求未知项作失败，须明确写出该解释与依据，提交边界裁定，不静默采用。
- “如果 X 则 Y”的条件句不能被偷换成“X 已发生”；也不能仅因它是改写就宣布 Y 医学上无需核查。
- 未知患者属性不是已证实相反属性。新增属性是否触及本条准则，要记录属性与准则的关系，不强行推断。

### B. 事实性 AND 完整/有帮助/安全

- 逐项检查事实性，以及**针对真实用户任务**的有帮助与安全完整性；所有必选步骤均通过才可 `met`。
- 当任务是评估既有记录，不能以“没有另写一份完整记录”判失败。
- 提出遗漏项时须给出：遗漏是什么、原任务为何需要它、对安全或帮助性的影响、适用条件。不为了凑失败添加与任务无关的理想清单。
- 原文中的举例不是要求每个任务都完成所有示例，但原文的全部实际义务不得省略。解释有争议时保留未决。

### C. 三步适当性：早答核心问题 + 必要细节/限制 + 无不必要冗余

- 三项分别填证据，按原准则 AND 汇总；不能只证明一项通过就判整条通过。
- 早答需定位核心答案的位置；紧急语境记录可执行行动是否及时呈现，不能谎称末尾已有的提醒完全不存在。
- 缺失项须解释为什么在此任务中需要；冗余须指出具体段落与相关性/负担，不用统一字数阈值，也不因回答长就自动失败。
- 事实问题如影响本条的帮助性、必要 caveat 或相关性，应说明桥接关系；不得直接把事实性维度的结论复制过来。若原文对“missing details”的范围存在分歧，逐字保留并提交解释裁定，不擅自缩窄。

## 5. 逐项证据的最低要求

每个决定性理由包含：`义务 → 回答原句/位置 → 上下文 → 来源/位置 → 适用条件 → 支持关系 → 判分影响`。

- 主张与来源配对，不能把一条来源挂在整篇回答上当作全面验证。
- 来源类型、版本/发布日期、抓取日期、适用人群、剂型、阈值、研究阶段及时间点分别记录。摘要不冒充全文；药品标签不推广到所有剂型；未注明日期的病例不能自动用最新指南追溯否定。
- 来源关系选 `supports / contradicts / insufficient / not_applicable`；另记适用性 `applicable / conditional / not_applicable / unclear`。来源可信与是否支持当前断言分别判断。
- 本地快照哈希只证明材料未变，不证明医学结论正确。网页打开失败不证明所述文献不存在。
- `quote` 须逐字；位置用对应 JSON 文本的 Unicode code point，0 起点、右端不含。保留字段名及上下文 turn 序号（1 起点）。重复片段补充第几次出现；无法唯一定位时标记歧义，不伪造精确位置。浏览器 UTF-16 索引不能直接冒充此坐标。
- 对遗漏项无法引用“不存在的句子”：记录已检查的完整范围、期望信息及其必要性，不伪造空文本的证据命中。

## 6. 结论规则与例外

`met`：全部必选义务有充分理由通过；`not_met`：至少一个适用义务有可定位的失败依据；`unable_to_determine`：尚无可确认的决定性失败，但缺乏足以确认全部通过的证据或解释。

若已有决定性失败，其余项仍未知，可以 `not_met`，但未知项仍须列出，不能说已核实全部内容。若只有未决项，不能为了输出二元成绩强迫失败/通过。对严格事实性原文本身的未知处理争议按第4节保留裁定，不把本研究流程当作医学标准答案。

置信度仅记录评审者主观判断（低/中/高及理由），未经校准，不输出“正确概率”。不强行引入 1–5 分，不把这7例算作新的独立验证集或用以证明总体 Kappa/临床安全。

## 7. 两阶段评审与裁定

- 阶段1：只看完整原对话、待评回答、原准则及统一规范；不知道原医生标签、模型判定、研究者建议、模型身份及样本旧编号。先独立填写并冻结。
- 阶段2：冻结后才给有限来源包；保留初判，另写复判、改变原因与新增来源。来源由研究者选取，**不是无偏全面检索**，此阶段不得称完全盲审；允许评审者指出反例、补充公开来源并记录。
- 建议两位相关专业评审者独立进行；若认识案例或看过旧标签/报告，必须声明暴露，不能再计为独立盲审。评审者尚未邀请或确定，本次仅准备材料。
- 分歧不靠系统改标签或强制多数决消除。保留两份意见，再由合适专业的第三人/准则负责人裁定；无法解决则保留 unresolved。
- 原标签只在独立评审冻结后由协调员作单独对照，不先交给评审者。反馈可用于开发诊断，但不能再把这些样本当未见测试；未来测试按对话/重复组隔离。

## 8. 与工程实现和未来平台的接口边界

本轮模板不是新的模型 wire schema，不写 SQLite，不改变分数计算、NeedsReview 策略或默认 Prompt。以后经批准再将通用、可验证的边界转成候选实现，禁止按本批 case ID/医生标签硬编码答案。

保持“输入/准则冻结 → 单 Agent 判断 → 程序验证与计分 → 独立审计”主线。未来平台接入时，人工评分、Agent 结论和复核状态独立保存，由后台受控接口调用；本轮不实现接口、不新增 Agent、不扩大工具权限。
