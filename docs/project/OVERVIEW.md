# 项目目的与边界

## 研究问题

医疗场景的模型回答是开放式文本，不能只用关键词或主观总分评价。本项目研究：能否让一个受控AI Jury依据明确Rubrics，对固定模型回答作可追溯的判断，并与独立医生标注进行比较。

长期方向是为医疗多智能体系统（MAS）的输出质检提供评估能力；现阶段先完成单一审查Agent，不同时扩大模型训练、界面和多Agent范围。

## 输入与输出

- 输入：原始对话、固定回答、适用的原始准则、经过批准的来源/元数据。
- 输出：准则是否满足、简短理由、回答/上下文定位、复核原因、版本和费用审计。
- 独立评测：原医生标签另存，预测冻结后再评分；不作为模型提示、向量检索或目标答案。

## 与原平台的关系

原平台负责病例、模型回答、医生独立评分与Admin管理；本Agent是独立Python研究服务。本仓库不包含原平台源码、数据库、医生账户或患者数据。未来经版本化后端接口接入，人工评分、Agent输出和复核状态分开保存，不覆盖已锁定人工结果。

## 明确不做的事情

不自动诊断/处方，不声称临床合规认证，不把文献成绩或目标数值写成实测；不通过篡改准则、参考标签或删掉失败来提高成绩。公开数据有医生标注不代表医生永远正确，也不代表基础模型训练从未见过这些内容。

当前结果尚不足以替代医生。优先目标是可验证、可解释、可复现，而非更多Agent或更大知识库。
