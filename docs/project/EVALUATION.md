# 公开医生对照：协议、结果及解释边界

## 数据与冻结

来源：[HealthBench官方meta-evaluation代码](https://github.com/openai/simple-evals/blob/main/healthbench_meta_eval.py)及[论文§8.1](https://arxiv.org/html/2505.08775v1)。公开记录有固定对话、completion、rubric和匿名医生二分类标签；不是仅有参考答案。

原始下载版本：healthbench-meta-2025-05-07，SHA256：`6a343ed3fcb6f28353c2c6c157ae30ddf2db874c947b27ba474ad54da9c5dbac`。本仓库不提供原始JSONL或标签，使用者应从官方来源下载并遵守其条款。

第15轮固定seed=1520261025，从项目validation里抽14个未运行/未索引对话组，7主题各2组，一组1条准则，不按标签平衡。标签保存在单独目录；模型消息只有固定输入和准则。所有预测/失败/未运行状态封存后，独立评分器才读取标签。该隔离不是对机器所有者的加密盲法，也不能排除模型预训练污染。

## 最新结果

| 口径 | 值 |
|---|---|
| 计划对话组 / 原医生标签比较数 | 14 / 29 |
| 医生全体一致 / 有分歧的组 | 10 / 4 |
| 当前基线有效 / 格式失败 | 13 / 1 |
| 有效子集比较数 / 一致数 | 27 / 13 |
| 有效子集agreement | 48.1481% |
| 有效子集Macro-F1 | 0.480769 |
| 有效子集Cohen Kappa | 0.045455 |
| 混淆矩阵 TP / TN / FP / FN | 7 / 6 / 11 / 3 |
| 整批主指标 | **null：覆盖不完整** |
| 新B1候选 | 3次2400-token截断；停止后11条未运行；无一致性成绩 |

该48.15%是**13条有效结果对应的27次医生标签比较**，不是13/27个患者，也不是14条完整批次的准确率。FP/FN按原准则met语义计算，不直接等于所有临床场景的安全漏检/误报。

按相同27次比较，“全部判met”一致率37.04%，全部判not_met为62.96%；后者Macro-F1仅0.3864，提示不能只看偏斜样本的accuracy。当前基线Kappa很低，尚无充分证据证明可靠医疗裁判能力。4组医生分歧也说明不可能同时匹配每位评审。

探索性分层对话组bootstrap 95%区间：agreement约[0.3846,0.5714]，Kappa约[-0.1333,0.2098]。每主题只有2组，区间不稳定，不能据此推广总体临床结论。

## 两类工程失败

- 基线1条返回6项answer_evidence，超过最多5项的契约，记录为格式失败；没有把原判强行当作有效输出。
- B1三态候选的3条均finish_reason=length、completion_tokens=2400，触发预注册停机；不将截断误称无法确定，不补造缺失JSON，也不重跑覆盖。

基线1200输出tokens与候选2400tokens、协议也不同，不能将两臂差异解释为单条Prompt修改的因果效果。B1原准则全文仅绑定为O1研究草案，无伪造医生批准的原子义务或额外医学来源。

## 正确报告指标的方法

逐医生原标签比较；二分类Macro-F1、Cohen Kappa、混淆矩阵、覆盖率与复核/失败分开。没有1–5医生评分就不计算1–5 MAE、Spearman或加权Kappa。共同有效子集必须标条件性，完整计划分母不丢弃。

工程测试数不是医疗样本数。Oracle提供原准则不证明RAG检索；定位存在不证明语义支持；文献结果和验收目标不能当本项目实测。

## 公开证据与不可公开部分

`benchmarks/summaries/latest.json`保存白名单聚合指标；`docs/project/RELEASE-VERIFICATION.json`记录发布包核验。原始病例、医生ID/标签、逐例模型回答、账本和带原文诊断不在仓库。历史精确复现需作者本地材料/原版本，不承诺克隆后复现相同外部模型随机输出。
