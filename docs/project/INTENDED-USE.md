# 预期用途与自动化分级（INTENDED-USE）

版本 0.1，2026-10-26。作者：项目负责人（LTF），文字由 Claude 协助整理。

**状态：草案。**文中的数字门槛都是**提议值**，需要与临床合作方和 PI 讨论确认后才生效。本文件不是临床或监管意见。

## 1. 目的

本项目开发一个**审查 Agent**，评审 A*STAR 医疗多智能体系统（WP3 平台）的输出。

- 远期愿景：由 Agent 自动完成这类审查，不再需要医生逐条审查。
- 本文件的作用：把这个愿景拆成可以逐级验证的自动化等级，写清每一级需要什么证据、可以接受多大的错误，以及有哪些监管含义。这样每一步改进都有明确的验收标准。

## 2. 审查对象与使用场景

| 项目 | 当前设定 | 依据 / 状态 |
|---|---|---|
| 被审输出 | WP3 医疗多智能体系统生成的**慢病管理 / 治疗建议**，如糖尿病、高血压、慢性肾病 | 负责人 2026-10-26 的工作假设；平台尚在开发，输出格式未定 |
| 输入数据 | MIMIC 或医院数据（有审批），以及公开或合成数据（HealthBench、BioNLP、MedExpert、Synthea） | 非公开数据按第 6 节记录审批 |
| 语言 | 英文（MIMIC）；中文待定 | 现有检索模型只支持英文 |
| 使用者 | 研发团队与临床审核人员 | 当前阶段 |
| 审查结论 | 逐条准则判定（满足 / 不满足 / 不适用 + 原文引用）、各维度评分、需人工复核的原因 | 对应 v3 流程 |

## 3. 自动化分级

| 等级 | 含义 | 谁做最终决定 | 进入该等级所需证据（提议） | 可接受的错误（提议，待临床确认） |
|---|---|---|---|---|
| **L0 研究原型** | Agent 只在离线环境中运行，结论不进入任何工作流 | 不适用 | 实现正确（测试、可复现）；在公开数据上与医生的一致性已报告 | 不适用 |
| **L1 初筛辅助** | 医生仍然审每一条；Agent 标出可疑之处，并给出准则依据和原文引用 | 医生 | ① 目标场景（平台输出或其代理）上，严重错误的检出率 ≥ 0.90；② 有医生对审查结论做过盲评；③ 按自动化偏差的要求设计人工复核界面（医生先独立判断，再看 Agent 结论；或者不显示 Agent 的分数） | 漏报允许存在，因为医生仍审每一条；误报率以不明显增加医生负担为准 |
| **L2 有保证地部分自动** | 只有在**经过校准、能保证与医生一致**的那部分样本上，Agent 才自动给出结论；其余转医生 | 被自动判定的部分由 Agent 决定，其余由医生决定 | ① 在**留出的目标场景数据**上，被自动判定部分与经过裁定的医生共识一致率 ≥ 1−α（例如 α = 0.10），且这一结论成立的概率 ≥ 1−δ（例如 δ = 0.10）；② 被自动判定部分中严重错误的漏检率 ≤ 0.02；③ 报告自动判定的覆盖率；④ 医生盲评至少 2 人，并经过裁定；⑤ 上线后持续监测，并定期抽检被自动判定的样本 | 由 α、δ 和严重错误漏检率共同约束；覆盖率是结果，不是目标 |
| **L3 完全自动** | 不再需要医生审查 | Agent | 在 L2 的基础上，还需要：① 前瞻性评估（静默部署期间，与医生决定做对照）；② 监管评估；③ 持续的上线后监测和退出机制 | 由临床与监管确定 |

**当前所处等级：L0。**下一个目标是 L2，L1 作为过渡。

## 4. 错误代价不对称

- **漏报**（把有严重问题的输出判为合格）的代价，远高于**误报**（把合格输出标为可疑）。
- 严重程度的分级应参考成熟的体系，例如 AHRQ 伤害分级、NCC MERP 用药差错分级，而不是自定的「严重 / 轻微」。
- 因此各等级的门槛以**严重错误的检出率**为核心，κ 和 QWK 这类对称的一致性指标只作辅助。

## 5. 目前的证据（截至 2026-10-26）

| 证据 | 结果 | 对应等级的哪项要求 | 差距 |
|---|---|---|---|
| HealthBench，给定正确准则（150 条全新样本） | κ 0.495，同一批样本上医生之间为 0.487 | L1/L2 的「一致性」，但不是目标场景 | 没能证明非劣效（CI 下限 −0.142）；样本不是慢病管理建议 |
| HealthBench，系统自己找准则 | 单 Agent κ 0.393；路由 + 评分 κ 0.317；路由准确率 0.70 | — | 选情境是瓶颈 |
| BioNLP 验证集（3 级量表） | 平均 QWK 0.151 | — | 打分尺度系统性偏严 |
| MedExpert 测试集（5 级严重度） | 事实错误 0.143，遗漏 −0.014 | — | 打分尺度不稳定 |
| 目标场景（慢病管理建议） | **无** | L1/L2 的全部要求 | 需要平台输出（或代理）、医生盲评 |
| 严重错误检出率 | **未测** | L1/L2 的核心要求 | 计划第 3 阶段用「已知答案」测试环境测 |
| 有统计保证的自动判定（第 1 阶段 v1 + v2，全新样本，给定正确准则） | **没有达到**：<br>· v1：只靠置信度阈值，α = 0.05 时覆盖率为 0；<br>· v2：只在 communication、hedging 两个主题上、且三次结论一致时才自动判定。补全后自动判定 234 条，错误率 4.7%，上界 7.0% > 5% | L2 的核心要求 | 在当前评分 Agent 下达不到 5% 的保证；先测出单个医生相对于共识的错误率，用它来设定目标；再考虑换不同家族的模型做第二评委，并改进偏严或偏宽的判断 |

## 6. 数据与合规

- **非公开数据**（MIMIC、医院数据）发送给外部模型服务，负责人表示已获认可（2026-10-26）。每次付费运行必须写明审批依据，格式为：

  `--data-approval-ref "approver=<审批人或机构>;date=YYYY-MM-DD;provider=<服务商>;scope=<数据范围与用途>"`

  四项缺一不可；`provider` 必须与本次实际发送数据的服务商一致。解析后的记录会写入运行计划和审计记录（实现见 `src/medical_jury/v3/data_approval.py`）。
- **参考**：PhysioNet 2025-09-24 的说明要求，外部服务应核实零数据留存、不用于训练、无人工查看。建议在 `scope` 中写明核实了哪些内容。
- 公开或合成数据（HealthBench、BioNLP、MedExpert、Synthea）不需要审批记录。
- 医生标签不能写进提示词，也不能放进检索内容；评测数据的划分、冻结、封存规则沿用各协议。

## 7. 监管提示（需由 A*STAR 的法务或监管人员确认）

- 用于诊断或治疗决策、并会影响临床处置的软件，在新加坡可能落入 HSA 对医疗器械软件（SaMD）的监管范围；L2，尤其是 L3，很可能涉及。
- 本项目在 L0 / L1 阶段属于研究用途。进入 L2 之前，应先确认监管路径。

## 8. 不声称的事

- 不声称临床有效，不声称可以替代医生，也不声称公开数据集上的结果能直接推广到平台输出。
- 不把公开数据集上的一致性数字，写成目标场景中的准确率。

## 9. 需要与 PI 和临床方确认的问题

1. 平台输出的类型与格式，以及何时能拿到样例。
2. 各等级的门槛（α、δ、严重错误检出率）由谁来定。
3. 临床合作方能否安排 2–3 位医生，每人盲评至少 50 条。
4. 合规算力的访问方式，以及非公开数据审批的正式记录。
5. 监管路径由谁负责。

## 10. 与行动计划的对应

| 阶段 | 服务于 |
|---|---|
| 1. 有统计保证的自动判定 | L2 的核心机制 |
| 2. 路由 v2 | 提升系统自己找准则时的一致性 |
| 3. 慢病「已知答案」测试环境 | L1/L2 的严重错误检出率（代理） |
| 4. 稳健性与规范报告 | 各等级共同的可信度要求 |
| 5. 医生、算力、平台输出 | L1/L2 在目标场景中的验证 |
