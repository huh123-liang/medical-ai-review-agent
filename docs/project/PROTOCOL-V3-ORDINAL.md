# v3 有序评分预注册协议（PROTOCOL-V3-ORDINAL）

制定日期：2026-10-25（第 4 步，离线）。本协议在**任何 v3 付费评分运行之前**写定。之后若修改，必须升版本号、写明理由，并且修改后只能使用新的、未见过的数据来证明效果。

## 1. 被评估的系统

v3 单 Agent 评审链中的**按维度锚定打分**：评分模型看到问题与固定回答，按评分档案中每个维度的量表与锚点描述给出整数分。这两个档案没有检查条目，只靠锚点打分。

- 档案：`kb/v3/profile-bionlp-safety-3level.json`（5 个维度，0–2 分）、`kb/v3/profile-medexpert-severity-5level.json`（2 个维度，0–4 分）。所有维度都是**分数越高越好**，由原始严重程度反向换算而来。
- 提示词、模型、调用模式（每个维度一次调用，或一次调用评完所有维度）在冻结时确定，见 §6。
- 本协议**不**评估情境路由和检索：这两个档案不含情境类准则。

### 2.1 BioNLP-TREC 的纳入规则（确定性规则，不看标签值）

1. 标注回答的文本（规范化空白和大小写后）在作者的 TREC 输出文件中，只对应唯一一个「行 + 问题版本」；
2. 该行该版本在 `combined_rephrased_TREC_temp_0.1.csv` 中的问题文本至少 15 个字符；
3. 5 个有序维度的标签都存在，且属于已知取值。

排除情况：354 条在作者输出中找不到（Me-LLaMA 13B 没有 TREC 输出文件，PMC-LLaMA 和 Meditron 只能对上一部分）；13 条对应多个单元格；3 条问题文本缺失；2 条标签缺失。

**选择偏倚**：纳入的条目偏向 Llama-3 和 Medalpaca 的回答。语义相似度只用作诊断，在已唯一匹配的 368 条中，91% 的问题排在语义相似度前三，**没有拿它来筛选**。

MedExpert 部分的 `combined_rephrased_MedQuAD_*` 文件里装的其实是 TREC 的问题，所以这份仓库里的 MedQuAD 子集无法还原问题原文，没有使用。

### 2.2 切分（不看标签）

按问题组切分，同一问题的所有回答进入同一个集合。按 `sha256(seed:group)` 的顺序遍历问题组，每组分给离目标比例最远的集合：BioNLP 为 dev 50% / validation 50%，种子 `ordinal-v3-bionlp-trec`；MedExpert 全部归入 test。各集合的组哈希记录在 manifest 中。切分完成后才查看了标签分布，**没有重新抽签**。

## 3. 指标

每个维度都计算以下指标。实现见 `src/medical_jury/evaluation/ordinal.py`：

- **主统计量**：二次加权 kappa（QWK），评分模型分别与**每一位**标注人的打分配对；类别取档案的完整量表；95% 置信区间通过按问题组重抽 2000 次的 bootstrap 得到。
- **次要统计量**：线性加权 kappa、完全一致率、相差 1 级以内比例、MAE、Spearman 相关、混淆矩阵、每个条目只取第一位标注人的 QWK、按标注人分别计算的 QWK、评分模型与标注人的分数分布。
- **覆盖率**：失败或未运行的条目保留在分母中。失败率超过 5% 时，主结论只作为条件性诊断，不下结论。

## 4. 主要与次要终点（预先写定）

### 4.1 验证（BioNLP-TREC validation，181 条，只跑一次）

- **主要终点**：4 个维度（missing_content、inappropriate_content、harm_extent、empathy）的**平均 QWK**及其按问题组的 bootstrap 95% 置信区间。
- **目标线**：平均 QWK ≥ 0.60（来自项目目标，不代表我们预期一定能达到）。不论是否达到，都按原样报告。
- harm_likelihood 只做描述（validation 中 176/181 为最高等级，QWK 不稳定），不计入主要终点。
- **无医生间参照**：公开文件中每条回答只有一位标注人。原论文报告过 TREC 部分 100 条共同样本的一致率（三人完全一致 63.88%，至少两人一致 98.29%），但那不是同一批条目、也不是 kappa，**不能当作上限**。部分标注人是医学生，结论要按「临床标注人」表述，不能称为「医生共识」。
- **文献背景**：BioNLP 2025 后续论文（Diekmann 等，LLMs as Medical Safety Judges）在同一套量表上，给 MedQuAD 部分每条回答补了两位标注，共三人标注，并报告了 Krippendorff α：不当内容 0.066、遗漏内容 0.127、伤害程度 0.266、伤害可能性 0.183、共情 0.440（来源：其 ACL Anthology 补充材料中的 `annotator_agreement.tex`）。这些三人标注数据**没有公开**，补充材料里只有论文源码，已于 2026-10-26 核实。这组数字只说明这些维度上人与人的一致性本身就很低，不是同一批条目上的参照，也不作为上限。

### 4.2 外部隐藏测试（MedExpert 全部 540 条，最终版本只跑一次）

- 报告 factuality、omission 两个维度的 QWK（附置信区间）以及 §3 的全部指标。
- **医生间参照**（32 条双人标注，运行前已计算并记录在此）：
  - omission：医生之间 QWK 0.197（95% CI −0.177 至 0.576）；
  - factuality：医生之间 QWK −0.238（95% CI −0.371 至 −0.138）。
  
  同时报告这 32 条上评分模型与医生的 QWK，以及差值的置信区间。
- **解读规则**：医生之间的一致性本身就很低，所以评分模型与医生的 QWK 必须对照这个参照来解读，不与 1.0 比，也不与 0.60 的目标线比。**不做非劣效结论**：32 条样本太小，置信区间过宽。

## 5. 开发规则

- 只能使用 BioNLP-TREC dev。允许在 dev 上修改提示词、用 DSPy 优化**指令**、选择调用模式和模型、拟合置信度校准。
- **不得把任何标签做成提示词里的示例或检索内容**：DSPy 只优化指令，不加带标签的示范。
- validation 和 MedExpert 在冻结前不跑任何付费评分；跑过之后再修改方法，对应数据就变成开发证据。
- 每次付费运行都要先出计划（调用次数、费用上限、剩余预算、数据流向、停止条件），获负责人批准后才执行。

## 6. 冻结清单（在跑 validation 之前写入 `reports/protocol-freeze-v3/<id>/freeze.json`）

档案文件 sha256、提示词版本与文本 sha256、模型名、temperature、max_output_tokens、调用模式、定位器版本、代码树 sha256、各数据集 manifest 的 sha256（包括切分组哈希和条目 id 哈希）、本协议文件的 sha256。

## 7. 费用与分批（2026-10-26 修订，此时尚无任何 v3 付费运行）

价格为每百万 token 输入 13.2 元、输出 39.6 元。剩余累计预算约 77.24 元。

**输出预留**：一次调用评完所有维度时，只靠锚点打分的档案每个维度预留 500 个输出 token，另加 400 个余量。BioNLP 共 5 个维度，合计 2900；MedExpert 共 2 个维度，合计 1400。每个维度单独调用时，每次预留 1200。输出被截断会记为失败，不会被当作有效分数。

**费用上限**：「上限」是预算闸门用的保守值，要求单次运行的上限不超过当时的剩余预算；「预期」是按实际用量估算的花费。

| 运行 | 调用次数 | 上限 | 预期 |
|---|---|---|---|
| BioNLP dev 试跑（按组抽取，seed `ordinal-v3-dev-subset-1`，49 条） | 49 | 11.4 | ≈4–5 |
| BioNLP validation | 181 | 41.3 | ≈17 |
| MedExpert test（分 3 批，每批约 31） | 540 | 91.9 | ≈28 |

**分批规则**（`--parts K --part k`）：只用于 validation 和 test，并按以下规则执行：

- 按问题组切分，切分时不看标签，分批结果是确定的；
- 每一批只能跑一次，分批数一旦确定就不能更改；
- 最后由 `scripts/aggregate_ordinal_v3.py` 汇总。汇总前逐批核对封存哈希、冻结记录，以及条目是否恰好覆盖全部。单独一批的结果只作为条件性结果。

**说明**：DSPy 优化，以及「一次评完所有维度」与「每个维度单独调用」的对照实验，都需要另行报预算。每一笔付费运行，都要先出计划，经负责人批准后才执行。

## 8. 不计算、不声称

- 不声称临床有效、可以替代医生，也不声称能推广到平台的 MIMIC 慢病病例；
- 不把 BioNLP 和 MedExpert 合并成一个总分；
- 不用 HealthBench 的二分类 kappa 冒充有序加权 kappa；
- 评分模型给出的置信度，在校准之前不作为结论依据。

### 9.3 对比规则

- **dev-B**：dev 中除 dev-A 以外的全部条目，用 `--n 40 --complement` 选出，共 133 条，此前从未运行过。
- **运行**：v3-dimension-2 和 v3-ordinal-1 都在 dev-B 上各跑一次，评分模型、调用模式、条目全部相同。

- **采用规则**：两次运行都满足覆盖率规则（失败率 ≤ 5%），且 v3-ordinal-1 的平均主要 QWK **高于** v3-dimension-2（差值点估计 > 0）时，才采用 v3-ordinal-1；否则保留 v3-dimension-2。
- **同时报告**：按组配对 bootstrap 的差值 95% CI，以及每个维度的平均差值。CI 跨过 0 时要写明「改进不确定」。
- **之后**：选定的提示词进入冻结（§6），不再修改。dev 数据到此已全部用过，之后的任何修改都没有未见过的开发数据可以验证。

### 9.4 dev-B 结果与决定（2026-10-26）

**两次运行**：

| 提示词 | 运行 | 完成情况 | 估算花费 | 平均主要 QWK（95% CI） |
|---|---|---|---|---|
| v3-dimension-2 | `ORD3-bionlp-trec-dev-20261025T170501Z-89797a` | 132/133 完成，1 条输出 JSON 格式错误 | 约 5.02 元 | 0.169（0.087 至 0.247） |
| v3-ordinal-1 | `ORD3-bionlp-trec-dev-20261025T170847Z-023bb7` | 133/133 | 约 4.52 元 | 0.154（0.080 至 0.229） |

**配对比较**：在 132 条（64 个问题组）上，差值（新 − 旧）为 −0.009，95% CI −0.085 至 0.063。

**按 §9.3 规则保留 v3-dimension-2**，不采用 v3-ordinal-1。新提示词也没有减轻偏严：missing_content 的平均差值反而从 −0.40 变成 −0.55。

**dev-A 偏乐观**：dev-A 的 0.36 明显高于 dev-B 的 0.17，说明 49 条的试跑数字偏高。按全部 181 条 dev 合并计算，v3-dimension-2 的平均主要 QWK 为 0.21。inappropriate_content 的 QWK 接近 0（−0.05）：标注人在 85% 的条目上给了满分。

**离线校准检查（不花钱，只作诊断，没有改动系统）**：

- 方法：在全部 181 条 dev 预测上，按问题组做 5 折交叉验证，重复 20 次。每个维度在训练折上选出使 QWK 最大的单调分数映射，再应用到留出折。
- 结果：留出折的平均 QWK 为 0.213（20 次范围 0.191 至 0.228），不做映射时为 0.210。第一次重复中差值的按组 bootstrap 95% CI 为 −0.021 至 0.053。
- 结论：重新映射分数几乎没有帮助，偏差不是一个简单的整体平移能修正的。**不加入校准层**。

**冻结前的结论**：按 §6 冻结 v3-dimension-2、一次调用评完所有维度、DeepSeek V4 Pro，然后在 validation 上只跑一次。根据 dev 结果，预计平均 QWK 远低于 0.60 的目标线，结果将按原样报告，并参照 §4.1 中人与人之间的一致性来解读。
