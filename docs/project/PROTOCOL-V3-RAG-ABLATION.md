# 第 6 步：评分准则选择消融预注册（PROTOCOL-V3-RAG-ABLATION）

制定日期：2026-10-26。本协议在**任何第 6 步付费运行之前**写定。运行开始后不再修改；若要修改，必须升版本号、写明理由，并且这次运行的结果只能作为开发证据。

## 1. 要回答的问题

医疗对话的评分准则往往取决于情境。例如同样是「何时就医」，紧急、条件性紧急、非紧急三种情境下的要求完全不同。实际病例不会预先标明属于哪种情境，所以系统必须自己找出适用的准则。本步比较以下三种做法，看哪一种的判断与医生更一致。

| 组别 | 系统 | 情境由谁判断 |
|---|---|---|
| `single` | **单 Agent**：评分 Agent 一次看到这个主题下所有情境的定义和对应准则，自己判断哪个情境适用，再按该情境的准则判定 | 评分 Agent 自己 |
| `rag` | **路由 Agent + 评分 Agent（RAG）**：路由 Agent（`v3-situation-router-1`）只读对话和知识库里的情境定义，先选出情境；评分 Agent 只拿到知识库中该情境的准则来判定 | 路由 Agent |
| `oracle` | **上限**：评分 Agent 直接拿到正确情境的准则，相当于 HealthBench 原本的设定 | 已知（金标准） |

三组使用同一个评分 Agent：提示词 `v3-dimension-2`，每次检查一条准则，二元判定档案，DeepSeek V4 Pro，temperature 0。三组也都知道主题和要评的方面，唯一的区别是**情境怎么确定**。

## 2. 数据

- **来源**：HealthBench meta-evaluation 的 **dev** 集（MIT 许可）。每条样本包含一段对话、一个固定回答和一条医生撰写的共识准则；至少 2 位医生对回答是否满足这条准则给出了判定。
- **抽样**：用 `natural_sample` 按对话组均匀抽 **150 组，每组 1 条**，种子 `20261026`，抽样过程不看标签。
- **排除**：此前任何付费 dev 运行用过的组，以及数据库和 iteration 材料中出现过的组。
- **不使用**：HealthBench validation 和 test 不在本步使用，留给 PROTOCOL-V2。
- **只抽一次**：路由阶段一旦正式运行，就会写入一次性哨兵，之后不能重新抽样。

## 3. 判定规则（预先写定）

- **评分 Agent 的结果换算**：`pass` 或 `not_applicable` 记为满足，`fail` 记为不满足。
- **RAG 组没有可评准则时**：包括路由选了「none」、路由调用失败、或所选情境下没有这个方面的准则。此时系统对这个方面「未评估」，记为满足（没有指出问题），并单独报告覆盖率损失。
- **单 Agent 组**：它判断的情境下没有这条准则时，按 `not_applicable` 处理。
- **调用失败的样本**：评分 Agent 调用失败的样本，不计入该组的统计，计入该组的失败率。

## 4. 指标

- **主要终点**：RAG 组与单 Agent 组 Cohen κ 的差值（κ_rag − κ_single）。κ 是评分 Agent 与每一位医生配对后计算的；两组只比较双方都成功的样本，95% 置信区间按对话组 bootstrap 重抽 2000 次得到。
- **主要终点的解读**：
  - 置信区间下限 > 0：RAG 更好；
  - 置信区间上限 < 0：RAG 更差；
  - 其他情况：没有证据表明两者有差异。
- **次要指标**：
  - κ_oracle − κ_rag（路由出错带来的损失）；
  - κ_oracle − κ_single；
  - 每组各自与医生间一致性的差值（Δκ，附置信区间）；
  - 在所有医生判定一致的样本上做 McNemar 检验；
  - 路由准确率（在正确主题内选中金标准情境的比例）、选「none」的比例、RAG 组的覆盖率；
  - 按主题拆分的结果（只用于排查问题）。
- **覆盖率**：任一组失败率超过 5% 时，主要终点只作为条件性诊断，不下结论。
- **定位**：这是开发阶段的消融实验，不是临床声明。不声称可以替代医生，也不声称能推广到 MIMIC 慢病病例。

## 5. 运行与费用

脚本为 `scripts/run_rag_ablation_v3.py`，分三个阶段，每一阶段都先出计划，经负责人批准后才执行：

| 阶段 | 内容 | 调用次数 | 上限（估算） | 预期花费 |
|---|---|---|---|---|
| route | 抽样并路由，每条样本调用一次路由 Agent | 150 | 约 22 元 | 约 3 元 |
| evaluate | 三组的评分调用；完全相同的请求只发送一次（RAG 选对情境时与 oracle 的请求相同） | 约 300–350 | 约 55–75 元，分 3 批，每批不超过约 26 元 | 约 9–11 元 |
| score | 所有批次封存之后才读取医生标签并计算指标 | 0 | 0 | 0 |

评分调用的输出上限为 800 个 token，超出算失败。停止规则与之前各步相同：遇到 401/402/403/429 或预算不足立即停止；连续 3 次失败停止；前 50 次中失败超过 5 次停止；不自动重试。

## 6. 不做的事

- 不把医生标签做成提示词里的示例，也不把它们放进检索内容。
- 不在看到结果之后修改提示词、准则、路由或判定规则，再重新运行同一批样本。
- 不用这次结果去调整 BioNLP 或 MedExpert 已经冻结的结论。
