# 离线验收方案：设计验证，不是临床正确性验证

版本：methods-acceptance-v1，2026-10-25。范围：文档和模板自洽性、已有离线回归重跑、未来评测设计。本轮不新增付费推理、不改运行核心或原平台。

## 1. 三层验收，分别报告

| 层级 | 本轮可以执行什么 | 本轮不能证明什么 |
| --- | --- | --- |
| L0 文档/计划核验 | 原始论文链接、P/G/A编号完整；模板空白；未决案例和文件/账本保持；方案不冒充结果 | 准则解释或论文方法在本项目上有效 |
| L1 已有工程回归 | 重跑原核心245、契约71、影子36项；以实际JUnit计数为准 | 新增30个设计场景已实现、模型判断变准或医学语义验证通过 |
| L2 未来能力评测 | 本轮仅定义Oracle/检索、Prompt对照、分层指标与停止条件 | 新Prompt效果、跨病例RAG质量、医生一致率提升 |

`acceptance-cases.json`所有A01–A30均为planned。本轮文档核验不执行这些计划的语义断言；部分与旧测试重叠也不重复累计成新增通过数。合成颜色/标点/日期文本可以用于后续协议最小对照，不是医学金标准。

## 2. 现有材料的用法

1. 七例：只检查固定原材料、未决状态和旧输出缺项；不作示例、训练目标或未见测试。本轮无需读取医生标签内容。
2. 历史模型输出：区分原始JSON和保存报告投影，不能从reason恢复模型未提供的逐项证据。不把旧字段缺失追溯改判失败。
3. 新模板：空白表和字段需求；不提交旧wire schema，不在正式库写新评分。
4. 公共医学标签：未来可用于独立meta-evaluation，必须标明逐医生标签、聚合方法及分组，不因“公开”就把验证标签放进Prompt。

## 3. 未来最小对照：只改一个因素

建议顺序：

- B0：冻结现有Prompt与输入，保留旧结果。
- B1：同样准则/病例/来源/模型，使用候选证据说明，不加入示例。
- B2：在B1上仅加入2–4个已审核开发示例；固定ID、顺序、版本和token预算。
- R0 Oracle：人工确认/病例绑定的准则直供，不检验检索。
- R1 Retrieval：相同冻结病例自动选择准则；先核查选择，再比较共同准则上的判断，并把漏选单列失败。

先B0/B1，后B1/B2，最后R0/R1；不把Prompt、示例、检索、模型同时更换。示例需要先核查来源与可复用范围；当前七例不符合此要求。没有可用示例时B2不得伪造执行。

离线回放只验证旧输出如何被检查/保存，不模拟新Prompt会生成的答案。非医疗合成例子只能验证定义明确的协议逻辑。真实B1/B2预测必须以后单独批准调用，且不能将其结果预填进本方案。

## 4. 指标与完整分母

- `protocol_valid_rate = 协议有效条目 / 全部计划条目`；同时列未启动、失败、截断、缺字段与取消。
- 已列义务覆盖：记录到的预期ID / 给定清单ID；单报草案/已确认，不能称医学覆盖率。
- 引用定位：正确定位的配对 / 声称有引用的配对；它不等于引用支持精度。
- 语义支持精度/覆盖：仅在独立审核主张与支持关系存在时计算；缺审核即not_measured，不填0或100%。
- 医生一致：在独立原标签和可比较预测存在时，报混淆矩阵、Macro-F1、Cohen Kappa；不用二分类强造1–5 MAE或加权Kappa。标签与预测适用同一原始命题，负向准则不倒置标签。
- 过严分歧：预测not_met、医生met的数量/医生met总量；误放行分歧：预测met、医生not_met的数量/医生not_met总量。负向准则须另外按有害行为语义解释，不能把字面的met直接叫安全放行。
- 含abstain/未决：单报覆盖率、复核率及已决子集表现；不能只删掉难例报告总体提高。成对对照用共同有效集，同时完整报告各臂失败及全部计划分母。未决不自动映射not_met。
- RAG：必检覆盖、跨病例/未批准泄漏、误选/漏选、可选Recall/Precision，Oracle和检索分开。不存在相关项时指标记N/A。
- 按任务、准则类型、回答长度/复杂性、数据来源分层；不以整体提高掩盖安全/复杂场景退步。以后有足量独立组时按对话/重复组bootstrap区间，不按同一病例多条准则当独立样本。样本不足时不稳定区间须说明。

## 5. 判定门与停止条件

工程硬门：无付费调用；旧代码/Prompt/API/配置/标签/索引/材料不变；正式账本任务数、费用行和费用指纹不变；全部既有测试通过且不放宽断言。网络测试只允许Windows内部事件循环socketpair，手动本机连接、外连和DNS仍禁止。

遇到写入旧平台、标签流入输入、跨组示例、伪造来源、历史原判被覆盖、未授权付费、旧测试失败时停止，保留失败报告，不能补写“通过”。临床争议和unsupported_logic进入待复核，不自动改分。

医学性能没有本轮验收门槛，因为没有新预测和独立审阅。不能声称0.60 Kappa等目标达成。未来是否接受候选需用户先确认任务、独立标注、误放行容忍度和费用上限；不得看完测试再定标准。

## 6. 可复现和独立检验

冻结代码、材料、来源目录、准则、示例、模型、Prompt和版本hash；记录来源URL/位置及查阅日期。报告保存命令、Python版本、JUnit、账本摘要与文件哈希。核验工具禁止联网，仅写新报告和隔离的pytest临时数据。

核验工具的通过只说明已定义检查执行一致。领域专家可独立检验临床语义，公开医生标签可复核统计结果，第三方可重跑工程检查；这三者不能互相替代。哈希不是医学真值、匿名化或强防篡改。

## 7. 完成后的目标与架构核对

逐项回答：是否仍是单Jury与确定性校验？是否区分事实/判断/标签？是否避免缺证据就失败？是否保留负向极性与原准则？是否保持平台/API兼容？是否保留未决和全部失败？是否只报告实际完成的验证？不符合任意项则先修正文档/测试边界，不开展下一阶段。
