## 一、方法、检测和结果

| ID / 原文与位置 | 作者怎么做、怎么检测 | 原论文结果及边界 | 本项目取舍 |
| --- | --- | --- | --- |
| P01 [HealthBench v1](https://arxiv.org/html/2505.08775v1)，§8.1、表6 | 医生写对话相关准则；裁判逐项判met/not_met；另用医生判断进行裁判meta-evaluation | GPT-4.1裁判Macro-F1=0.709；是Consensus准则上的裁判指标，不是Kappa或医疗回答正确率 | 采用逐项、分组、独立标签验证。不能将公开病例准则自动提升为通用医学标准。 |
| P02 [LLMEval-Med v3](https://arxiv.org/html/2506.04078v3)，§3.3、§4.2 | 专家checklist分核心/次要要求；比较自动与人工可用性判断，检查任务差异 | §4.2四类MK/MR/MLU/MSE合计一致率92.47%；MTG较弱，作者用人工结果。§3.3另有92.36%表述，本文不把两者混成统一结果 | 采用任务分层、必要性说明、误放行分析；不复制其安全否决为“证据不足就危险”。无专家时清单仅研究草案。 |
| P03 [TALEC v2](https://arxiv.org/html/2407.10999v2)，§4.1–4.2、表4、§5.2 | 拆分领域准则；分别zero/few-shot再组合；用业务人工标注和测试集检验 | 表4 Knowledge QA Spearman .5063→.7089，情感 .9693→.9485；前者是组合方法差异，不是准则拆分单独效果。非医疗；示例可能使裁判漏掉真实错误 | 保留逐项判断，先做单因素无示例/少量例子对照；不立刻增加三轮调用或按旧标签修改准则。 |
| P04 [Many-Shot ICL v6](https://arxiv.org/html/2406.11629v6)，§2–3 | GSM8K数学回答；改变示例量/理由、提示表达；评稳定性与理由质量，并检查顺序/符号偏差 | 带理由示例可改善相关实验表现；部分质量比较由模型完成。没有可迁移为医学Kappa的数值；稳定不等于正确 | 将记忆限定为有审核来源的开发示例。我们拟试2–4例是预算友好的设计，不是论文最佳值。 |
| P05 [TextGrad v1](https://arxiv.org/html/2406.07496v1)，§3.3、表3、附录E | 语言反馈提出Prompt候选，验证集决定接受/回滚；不是更新裁判模型权重 | GSM8K Prompt优化准确率72.9%→81.1%；前向gpt-3.5-turbo、反馈gpt-4o。不是医疗裁判指标，也不是本项目已接入结果 | 暂缓自动优化，借鉴候选版本/验证/回滚规则。测试标签不能进入优化器，不能用自评闭环证明正确。 |
| P06 [PH-LLM](https://arxiv.org/abs/2406.06474)，摘要 | Gemini微调；睡眠/运动纵向数据，专家病例与领域Rubrics，另测知识与预测 | 专家协作构建857个病例；运动任务与专家无显著差异不等于证明等效，睡眠仍专家更好。不是通用审查Agent验证 | 后续纵向病例适配时参考任务和时间边界；当前不转向模型微调或可穿戴任务。 |
| P07 [ALCE](https://aclanthology.org/2023.emnlp-main.398/)，摘要及论文引用评价部分 | 检索证据、生成带引用回答；分开评回答正确性与引用支持/覆盖，自动评价辅以人工核验 | ELI5上最佳模型仍约50%的回答缺完整引用支持；非医疗，不是本项目错误率 | 新补充参考。引用ID/位置正确后仍需检查语义支持和适用性；不把NLI或另一个LLM当医生真值。 |
