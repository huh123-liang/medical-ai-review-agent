# 离线控制层修复 / grounded-review-v2

## 目的与状态

解决两个已定位的问题：用户粘贴材料中的词触发错误任务识别；证据不足或复核标记不足被当成整个输出失败。候选已经接入本项目的Provider/Workflow配置，但**没有替换本机默认scoped-review-v1、没有新模型测试、没有接入旧平台**。模型配置仍为V4 Pro，未新增付费调用。

该版本是单Agent内部策略修复，不是新医疗规则库、不增加Agent、不新增向量索引或网络工具。

## 改动

### 任务提示 task-spec-v3

- 将可识别的信件、Draft/Original/Source区块、引号和代码标记为数据区域，保留原文位置。
- 算法线索需与明确请求动作绑定；short course不再单独成为篇幅要求。
- 识别病历转换、病历评估、句尾改写和混合医疗/语言任务；历史改写只作为线索，不强制覆盖新任务。
- 提示与模型任务标签冲突只触发复核，不自动认定模型错，也不更改met/not_met。
- 这些仍是有限启发式，不是完整自然语言指令解析器；不声称覆盖任意格式、多语言、否定和隐式意图。

### 独立审阅策略 review-policy-v2

保留七字段模型wire及五字段公共Judgment。内部审计单独保存：

| 字段 | 语义 |
| --- | --- |
| model_verdict / model_reason | 模型原判定及原理由，不自动修改 |
| model_review_required | 模型原复核标记，和程序策略区分 |
| protocol_status | JSON、字段和ID是否合法 |
| task_status / task_spec | 非权威任务线索、冲突和混合意图 |
| evidence_status | 无绑定证据、部分主张未决或部分主张已评估 |
| policy_status / review_reasons | 程序独立决定NeedsReview及原因 |

没有外部证据不会自动变成not_met；不确定来源关系也不再被当作非法JSON。程序可以将公共review_required升为true，但模型原标记另存、不冒充模型自己要求复核。模型判定和理由保持原样，因此原理由中的语义错误不会被解析器悄悄“修好”。

未知/重复/错类型证据ID、超限字段、错误布尔类型、伪造fact_id、未绑定claim、重复来源配对、重复JSON键仍然失败。新增来源绑定子错误便于诊断。基准模式仍禁止abstain，不引入新的医生金标准标签。

当前没有独立验证的完整医学主张清单和证据覆盖，因此候选所有结果仍NeedsReview，可用weighted_score为空，研究分数和原判定保留。这不是经过校准的自动选择性放行系统，也不能用“零放行”证明临床安全性。

## 本轮验证

审计12条已见案例，8份原始输出与原SHA256一致；另15份成功报告只做规范化投影检查，1份截断记录跳过。回放先复现8份原错误，再验证新策略进入有效研究结果+需复核。保存原判定与理由，不更新历史job状态，不计算新的医生一致率。

回放期间显式拦截socket连接和httpx发送；调用前后原任务数量、费用记录与费用哈希一致。对照与病例细节见reports/iteration-8-offline/。pytest使用临时库和Mock，不调用付费模型。

已有源报告与冻结快照保留。旧第7轮runner要求“当前代码等于当时冻结代码”，因此改版后直接运行会安全拒绝；重现旧版本应使用before-code或第7轮frozen-code快照，不能篡改旧freeze来绕过。

## 使用与下一步

- 日常离线回归仍可运行Run-Offline-Test.cmd。没有自动切换到新付费配置。
- grounded-review-v2是注册的实验profile，未经后续授权与质量验证不设为默认；本轮不要求用户重跑API。
- 回放脚本scripts/replay_iteration8_offline.py保留一次性结果目录保护；已有after-code时会拒绝覆盖。新回放需要新结果目录/新版本，不删除旧结果来重跑。
- 下一步针对已审计的来源冲突、记录新增断言及过严/过松判分做证据级复核；需要新模型试验或独立临床裁定时另行确认。不在这12条诊断集上追逐一致率。
