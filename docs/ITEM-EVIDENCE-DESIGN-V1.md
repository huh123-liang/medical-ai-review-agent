# 逐项证据输出 v1：离线候选设计

状态：2026-10-25；独立实验设计，未接入 Provider、Workflow、API、SQLite 或旧平台。未新增付费调用。此前7条案例继续 unresolved，没有医生盲审结论，不进入 gold labels、训练目标或新测试金标准。

## 1. 这轮解决什么，不解决什么

现有 structured-ids-v1 每条准则最多3个回答片段、2个上下文片段、2项来源检查；可以记录局部依据，但不能证明复杂回答的逐项义务或全部断言已核实。现有 review-policy-v2 已把证据不足与无效协议分开；本设计保留该原则，不用“缺证据”强迫 not_met。

本轮只做：候选输出契约、独立离线检查器、合成对照测试，以及旧输出缺项盘点。**不改现有七字段 wire / 五字段公共 Judgment，不切换默认配置，不生成新医学判定，不用旧研究意见补造字段。**

实现只在 `experiments/item-evidence-v1/`，不被 src/medical_jury 导入。实验结果在 reports/iteration-11-item-evidence/。不是第二个 Agent，也没有新增联网、工具执行或自由检索权限。

## 2. 候选数据流

冻结原始对话/回答/准则 → 绑定义务清单和本地来源目录 → 单Agent候选输出 → 结构/绑定/逻辑核验 → 保留原判 + NeedsReview + 审计。

调用前的应用输入独立于模型输出，包括：

- case / rubric / obligation_manifest / source_catalog 四项 SHA256 绑定，防串病例、串版本、串来源。
- 无损文本目录：A=待评回答，C1..Cn=完整历史各turn，S1..Sn=提供的来源片段；包含角色、文本和哈希。不得混入医生标签。历史助手内容不升级成外部证据。
- 义务清单：原准则条文的精确位置、必选项ID及 AND 关系；只支持本轮明确的合取准则，不假装覆盖任意OR、条件分支或所有医学标准。范围不适配时停留研究状态。
- 清单权威状态：`research_draft / independently_confirmed / synthetic_fixture`。模型无权把草案改为已确认。当前7例没有经独立确认的义务清单，不能据“全部已列项通过”声称准则全部满足。
- 可选任务线索只用于冲突提示，不是权威任务解析器；不从粘贴信件中的词自动生成要求。

## 3. 模型输出字段（详细 JSON Schema 随离线报告导出）

| 字段 | 作用 | 不能代表什么 |
| --- | --- | --- |
| protocol_version + binding | 指定候选协议、冻结输入哈希 | 不是标签或正确答案 |
| model_verdict / model_reason / model_review_required | 模型研究用二元原判及简短理由/复核标记 | 不被程序覆盖成新结论 |
| task | 任务类型、原请求证据位置、不确定点 | 定位有效不等于任务识别正确 |
| claims | 逐项断言、原文位置、条件范围、模型声明的核查状态 | 模型自称列全不等于真实覆盖全部 |
| obligations | 每项准则义务的 pass/fail/unresolved、关联断言、证据、遗漏项与理由 | 义务草案不能冒充原准则的权威拆解 |
| checks | 断言与已提供来源配对、关系和适用性 | 来源命中不等于语义支持已验证 |
| coverage | 自报完整/部分/未知、未决断言和局限 | 不输出医学覆盖率或校准置信度 |

位置使用 doc_id、该文档SHA256、0起点Unicode code point起止坐标（右端不含）、原文quote。逐字匹配，重复内容靠坐标消歧；不得模糊修复、自动缩减清单或把UTF-16位置当成同一坐标。来源配对只接受应用提供的S类目录，不接受模型自由造URL；上下文仅能证明原文说了什么，不能直接作为独立医学事实来源。

遗漏项用专门 `missing_item`：缺项内容、已检查文档范围、其必要性。不能伪造“空句子命中”作为不存在的证据。程序只能确认检查范围有效，不能证明真的存在遗漏或遗漏足以扣分。

边界：最多40项主张、12项义务、48项来源配对；文本、列表和整份JSON有长度上限。达到边界不能悄悄丢掉剩余内容或声称完整；须说明范围缺口并继续复核。上限是实验防护，不是证明复杂病例已覆盖；未做真实模型token/费用评估。

## 4. 检查器输出：不替模型改判

- `protocol_status`：valid / invalid，区分JSON/类型/字段/越界、输入哈希错配、伪造ID、重复ID及无效位置。明确错误失败但不改模型结论。
- `structural_coverage`：只计算已提供的义务ID覆盖，不称医学覆盖；草案缺掉的真实义务不能被这个比例发现。
- `declared_conjunction`：仅汇总模型自报的逐项状态；只要缺项或未决且无失败就是 undetermined，不能改成自动失败。所有已确认必选项均pass可给声明层met，但不是临床通过。
- `consistency_flags`：原判与逐项自报冲突、部分证据被称完整、未决未列、来源适用性不明、任务线索冲突等。它们是复核原因，不是医学错误证明。
- `policy_status=NeedsReview`、`clinical_release=false`、`benchmark_export_eligible=false`、`score=null`：本候选始终不自动临床放行；保留原判，不把完全保守放行策略吹成已验证的安全系统。

合法但证据不足的输出，仍 valid + NeedsReview。已证实来源绑定存在但关系仍未知时不失败；“主张关系可定位”与“关系判断正确”分开。即使合成测试全通过，也没有事实核查或评分性能的新证据。

## 5. 七例及旧输出怎么处理

七例的第一阶段盲审材料已白名单导出完整原文。本轮从该目录读取；所有 review_id 状态明确为 `unresolved_no_independent_review`，不读取原医生标签或研究建议作为测试目标。旧结果如需盘点，只查看既有记录结构，不按叙述推断新字段；有原始字符串时记录其哈希，无原始字符串时明确只检查保存报告的投影，不称原始模型回放。

旧版不会因不含新字段就被追溯改成失败。兼容性输出是 `legacy_requires_new_instrumentation`：历史结果保持原状，新的逐项覆盖结论为 unknown。新格式需要将来授权后真实生成或由独立审阅者填写，不能离线“升级”出新医学证据。

## 6. 离线验证范围与验收

三层分开：

1. 协议/绑定测试：严格JSON、额外字段、类型、哈希、来源ID、重复ID、精确位置、Unicode、上限、跨病例错配。预期来自协议定义。
2. 最小对照/逻辑不变式：在人工合成的非医疗玩具文本中，只改一个因素，确认证据不足不是失败、未决不改原判、AND不漏项、假引用不放过、历史助手不是独立来源、任务线索冲突只复核。预期来自明确输入结构，而不是医学判断。
3. 七例完整性和旧格式差距：验证原对话/回答/准则未变；全部继续未决；不补全旧输出、不计算一致率/Kappa。预期只是不被篡改。

所有测试封锁网络，只读正式账本，不调用Provider，不写业务库。保存机器结果、测试报告、依赖版本、代码/输入清单及前后核验；冻结既有核心、基准标签、盲审材料与来源记录。验收是“契约可执行且保护边界”，不是医学正确性。

## 7. 本轮之后的审批门

先审阅契约是否符合实际成本与复杂度，并明确谁确认义务拆解及医学来源适用性。没有医生时保持未决；可继续做非医学结构测试，不能把另一个LLM自评当独立金标准。

下一步若获批准：实现可开关、非默认的影子适配层，沿用单Agent权限边界，与旧输出并行保存但不参与最终计分；先只做Mock和历史兼容性。再单独申请少量付费测试及预算，使用新未见开发组做真实生成验证。平台集成、多Agent扩展、本地部署、DSPy/TextGrad均不在本轮范围。
