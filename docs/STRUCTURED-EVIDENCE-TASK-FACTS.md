# 第7轮实现说明：证据ID、TaskSpec v2、有限来源核查

## 本轮目标与架构

目标仍是用一个可审计的研究裁判评估固定回答，而非生成治疗意见或冒充医生。独立项目不改MVP2、不上传GitHub、不复制患者库。未来平台仍从后端调用独立评估API，模型凭据不得进入浏览器。

流程：输入和原准则 → 无损证据目录 → 最新任务线索 → 可选窄范围来源卡 → 同一次V4 Pro判断 → 严格校验 → 还原原文位置 → 研究分数与复核门 → 审计。

## 1. 结构化证据

旧协议要求模型抄写原文，容易少字、多字、引文过多。实验协议改为提供带来源哈希前缀的片段ID，模型最多选3个回答片段和2个上下文片段；程序根据原输入还原原文、字符与UTF-16位置。连续分段不丢字符。未知、重复、错类型ID直接报错，不自动修补输出或改判。

ID定位成功只证明“这段文字来自这里”，不证明“这段证据足以支持判断”。目前片段通常不超过480字符，并非精细到独立医学命题。

## 2. 任务识别

TaskSpec v2从用户上下文中定位句首/句尾改写、邮件撰写、明确算法、简短/紧急/展开要求；屏蔽引号和代码里的命令，保留历史线索但优先最新任务。不从候选答案反推用户意图，也不把提及医生当成用户一定是医生。

明确外层指令与模型返回的task_kind冲突会失败，不以程序代替模型改判。规则仍是启发式；无法穷尽多语言、否定、讨论算法但不请求算法等情况。任务类型不能直接决定准则是否满足。

## 3. 有来源事实核查

本轮仅有4张经研究性来源核对的卡：口服阿立哌唑的肝功能调整、芬太尼代谢、锂与RAS药物相互作用、莱姆病单次预防的年龄范围。来源为DailyMed/CDC；保留章节、适用限制、下载日期、原始快照及SHA256。不是医生批准的通用指南库。

来源下载由操作员显式脚本完成；模型不联网、不调用shell、不写文件。运行时只检索本地卡，要求claim_id绑定已选回答片段、fact_id属于本次提供的来源，并记录supports/conflicts/uncertain和适用范围。

无命中不等于回答错误；有命中不等于整答正确。当前4卡按主题词匹配，不是医学事实向量库；原100条病例绑定Rubrics向量索引保持不变。来源卡与评分准则、原医生标签分库存放。历史病例不得悄悄适用当前指南。

## 输出与未来兼容

内部七字段为judgment、reason、answer_ids、context_ids、review_required、task_kind、fact_checks；转回原五字段Judgment，任务/来源审阅另存报告与审计。原平台未来无需直接解析新的模型wire格式。

grounded-review-v1仍强制研究/复核用途，供放行的weighted_score为空；research_weighted_score与原二分类判定保留。这避免把“来源ID有效”包装成临床通过。默认Prompt是否升级由完整回归和新样本结果决定，不能只凭离线测试成功。
