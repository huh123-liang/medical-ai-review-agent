# 第三轮：逐步目标与架构检查

本轮授权：引用定位、9条医生一致标签分歧的逐项分析、相同70条的受控对照；累计费用不得超过30元，不修改MVP2，不接入平台，不增加多Agent。

## 总目标与本轮边界

目标是建立可审计、可比较、未来能服务于医生评审平台的单Agent裁判，不是为了让9条开发样本全部命中标签而硬编码答案。

保持：病例输入 → 准则获取 → 快照 → 单次LLM判断 → 确定性证据校验 → 计分 → 审计。医生标签仅用于离线分析和指标计算；不进入LLM输入。Rubrics检索与医学事实检索不同，本轮不增加事实检索工具或疾病专属知识规则。

## 检查门

1. 引用定位完成后：验证只进行允许的排版等价匹配、原文位置唯一、原文hash与Python/浏览器偏移可追溯；不能改变数值、单位、否定、左右或判断。旧结果不覆盖。未来平台仅需读取新增证据定位数据，不接触Key或替代医生评分。通过后才开展病例分析。
2. 九条分析完成后：逐条对照原病例、原回答、原准则及医生标签；区分可观察误解、事实争议与标注不确定性。不得把与标签不符自动等同临床错误。只提炼通用评判原则，不把病例答案注入新Prompt。通过后冻结实验协议。
3. 同题对照前：冻结相同70条及顺序、Prompt/证据策略版本、代码hash、费用上限与预先定义指标。两组使用相同证据解析器，隔离Prompt影响；按预定顺序交错运行且不重试。旧v2严格引用结果只作历史参照。
4. 同题对照后：同时报告覆盖率、首次失败和配对共同有效子集，不挑选较好结果覆盖旧版；若新Prompt退步则保留旧默认。70条已用于开发分析，不能当独立验证或证明临床泛化。未完成独立验证前不接入原平台。

各步骤的实际证据与通过/不通过判断分别写入 `reports/iteration-3/gate-1.json` 至 `gate-4.json`，每完成一步即保存。此文档不是“已通过”的证明。
